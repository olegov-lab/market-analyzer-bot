# QA Checklist — AI BTC Monitor (Production Launch)

## 1. Telegram Integration

### 1.1 Init Data Validation

| # | Test | How To Verify |
|---|------|-------------|
| 1.1.1 | Подделанный `hash` в initData | Отправить запрос к любому `/miniapp/*` эндпоинту с `X-Telegram-Init-Data: hash=ffff...&user=%7B%22id%22%3A123%7D`. Ожидать `401 Invalid init data`. |
| 1.1.2 | Истёкший `auth_date` в initData | Telegram initData содержит `auth_date` (timestamp). Проверить, что бэкенд не принимает данные старше 24-48 часов. Сейчас `verify_telegram_init_data()` проверяет только hash, но не `auth_date`. **Нужно добавить проверку:** `if time.time() - int(parsed.get("auth_date", 0)) > 86400: return None`. |
| 1.1.3 | Пустой initData | Вызвать API без заголовка `X-Telegram-Init-Data`. Ожидать `401`. |
| 1.1.4 | InitData от другого пользователя | Взять валидный initData пользователя A, подставить в запрос с `user_id` пользователя B. Проверить, что API возвращает данные пользователя A (это корректно — user_id берётся из подписи, а не из тела запроса). |
| 1.1.5 | Повторное использование initData | Telegram initData одноразовый? Нет, он действует直到 `auth_date` + ~24ч. Но бэкенд не хранит использованные hash. **Рекомендация:** добавить Redis-сет `used_init_data_hashes` c TTL = 86400, чтобы reject повторное использование. |

В `app.js` используется `document.documentElement.setAttribute('data-sentiment', ...)`, но нет смены темы. **Нужно добавить:** чтение `Telegram.WebApp.colorScheme` и установка `data-theme` на `<html>`. |

## 4. Load & Security

### 4.1 Нагрузочное тестирование

| # | Test | How To Verify |
|---|------|-------------|
| 4.1.1 | Определить базовую нагрузку | Установить `k6` (`winget install k6`) или Locust. Написать скрипт, который GET `/miniapp/dashboard` 50 concurrent users в течение 1 минуты. Ожидать: p95 < 2s, ошибок < 1%. |
| 4.1.2 | Стресс-тест Postgres | `k6` скрипт с запросами к `/btc/price` и `/btc/indicators` (100 concurrent). Следить за `pg_locks`, `connection_pool`. Текущий pool_max = 10 для api контейнера. |
| 4.1.3 | Redis under load | Те же запросы. Проверить, что `redis_client.get(cache_key)` не падает. Кэш включён для `/miniapp/chart` (TTL 30s), `/miniapp/dashboard` и т.д. |
| 4.1.4 | Rate limiting | Отправить 100 запросов за 10 секунд к любому эндпоинту. Проверить: `slowapi` возвращает `429 Too Many Requests` (лимит: 30/min для большинства эндпоинтов). |
| 4.1.5 | Долгая нагрузка (soak test) | Держать 20 concurrent users 30 минут. Следить за памятью контейнеров (особенно LightGBM в scheduler). |

### 4.2 Стресс-тест стека (пример k6)

```javascript
import http from 'k6/http';
import { check, sleep } from 'k6';
export let options = {
  stages: [
    { duration: '30s', target: 20 },  // ramp up
    { duration: '1m', target: 50 },   // peak
    { duration: '30s', target: 0 },   // ramp down
  ],
  thresholds: {
    http_req_duration: ['p(95)<2000'],
    http_req_failed: ['rate<0.01'],
  },
};
export default function () {
  let res = http.get('https://btc.smartmarkettoday.com/health');
  check(res, { 'status 200': (r) => r.status === 200 });
  sleep(1);
}
```

### 4.3 Безопасность окружения

| # | Test | How To Verify |
|---|------|-------------|
| 4.3.1 | `.env` не в git | `git check-ignore .env` → должен вернуть путь (файл проигнорирован). `git ls-files .env` → ничего. `.env.example` — в git, это норма. |
| 4.3.2 | Файлы с secret на сервере | `ls -la /root/market-analyzer-bot/.env` — проверить `chmod 600` или `640`. Сейчас сервер использует `env_file: .env` в docker-compose. |
| 4.3.3 | API ключи не в image слоях | Docker image может сохранить ARG/ENV в слоях. В текущем `Dockerfile` нет `ENV` с секретами — только `COPY . .`. Все секреты передаются через `env_file` в runtime. ✅ |
| 4.3.4 | Cloudflare Tunnel без доступа в обход | `cloudflared` туннель — единственный вход на сервер. Проверить: `iptables -L -n` — порт 8000 (API) должен быть открыт только для localhost. ✅ (в docker-compose: `127.0.0.1:8000:8000`). |
| 4.3.5 | Telegram Bot Token не засвечен | Проверить: `grep -r "$TELEGRAM_BOT_TOKEN" .git/`. Также проверить, что токен не логируется. **Нужно:** убедиться, что `loguru` в `api.py` не логирует заголовки запросов. |
| 4.3.6 | CORS настроен строго | В `api.py`: `allow_origins=[settings.miniapp_url_normalized]` — только один origin. ✅ |
| 4.3.7 | Rate limiting на всех эндпоинтах | Проверить, что каждый `/miniapp/*` эндпоинт имеет декоратор `@limiter.limit(...)`". Сейчас все эндпоинты кроме `/miniapp/` (статический файл) и `/health` имеют лимиты. |
